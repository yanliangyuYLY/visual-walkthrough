# Visual Walkthrough 主动可视化规则

作者：a

在满足以下场景时，主动使用本插件提供的可视化能力，提升信息密度与交互直观度：

## 1. 何时主动输出「声明式交互组件卡片」（`ui-card`）

当发生以下情况之一时，主动按 `ui-card` 技能调用 `render_ui_card` 工具：
- 输出逐字段排查报告、Bug 根因对照表或 Code Review 清单（优先使用 `findings` + `diff` + `metrics`）；
- 需要审批多步骤实施计划或让用户挑拣/批注修改建议（使用 `plan` 并开启 `commentable: true` 与 `allowCustomInput: true`）；
- 对比多个技术方案需要权衡取舍（使用可本地调权的 `decision` 积木或 `table` + `actions`）；
- 内容较丰富易超过内联 `800px` 高度时，使用 `tabs` 分栏收纳。

## 2. 何时主动输出「逻辑讲解卡片」（`logic-walkthrough`）

当发生以下情况之一时，主动按 `logic-walkthrough` 技能核实真实代码与行号并调用 `render_logic_walkthrough` 工具：
- 向用户讲解超过 3 个步骤的代码执行流程、数据解析流水线、权限校验链路或状态机流转（推荐为 Mermaid 关键节点补充 `nodeDetails` 实现点击联动步骤）；
- 总结刚刚完成开发或重构的核心模块工作原理，且涉及多个函数或文件跳转；
- 用户询问“这段逻辑怎么跑的”“核心流程是什么”“帮我梳理一下架构或调用链”。

## 3. 何时主动输出「可交互视觉原型」（`visual-prototype`）

当发生以下情况之一时，主动按 `visual-prototype` 技能先生成可交互 HTML 原型：
- 为移动端、小程序或 Web 页面设计新界面、复杂表单交互、弹窗状态或冲突提示流；
- 用户提出 UI/交互改动需求，但在动手改业务代码前需要确认页面布局、交互路径或异常态表现。

## 4. 克制边界（不要主动触发的情况）

遇到以下情况时保持简洁纯文本或常规代码修改，**不要**强行生成图表、卡片或原型：
- 简单概念问答、单行命令说明、报错排查的一句话定位；
- 纯配置文件、文案微调或无状态交互的小改动；
- 用户明确要求“直接改代码”“只要文字说明”或“不用画图/原型”。
