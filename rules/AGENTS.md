# Visual Walkthrough 主动可视化规则

作者：a

在满足以下场景时，主动使用本插件提供的可视化能力，提升信息密度与交互直观度：

## 1. 何时主动输出「声明式交互组件卡片」（`ui-card`）

当发生以下情况之一时，主动按照 `ui-card` 技能调用 `render_ui_card` 工具：
- 输出逐字段排查报告、Bug 根因对照表、性能/方案对比矩阵；
- 给出多个可行修复或重构选项，适合让用户直接点击按钮确认下一步（通过 `send` 按钮一键发回对话执行）；
- 需要在同一张卡片中组合表格、状态徽章、Callout 结论/建议框、流程图或操作按钮。

## 2. 何时主动输出「逻辑讲解卡片」（`logic-walkthrough`）

当发生以下情况之一时，主动按照 `logic-walkthrough` 技能整理真实代码结构并调用 `render_logic_walkthrough` 工具：
- 向用户讲解超过 3 个步骤的代码执行流程、数据清洗/解析流水线、权限校验链路或状态机流转；
- 总结刚刚完成开发或重构的核心模块工作原理，且涉及多个函数或文件跳转；
- 用户询问“这段逻辑怎么跑的”“核心流程是什么”“帮我梳理一下架构或调用链”。

## 3. 何时主动输出「可交互视觉原型」（`visual-prototype`）

当发生以下情况之一时，主动按照 `visual-prototype` 技能先生成可交互 HTML 原型：
- 为移动端、小程序或 Web 页面设计新界面、复杂表单交互、弹窗状态或冲突提示流；
- 用户提出 UI/交互改动需求，但在动手改业务代码前需要确认页面布局、交互路径或异常态表现。

## 4. 克制边界（不要主动触发的情况）

遇到以下情况时保持简洁纯文本或常规代码修改，**不要**强行生成图表、卡片或原型：
- 简单概念问答、单行命令说明、报错排查的一句话定位；
- 纯配置文件、文案微调或无状态交互的小改动；
- 用户明确要求“直接改代码”“只要文字说明”或“不用画图/原型”。
